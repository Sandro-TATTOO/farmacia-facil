3. PROBLEMAS ENCONTRADOS
----------------------------------------------------------------

🔴 CRÍTICOS — Precisam ser resolvidos logo
─────────────────────────────────────────────────────────────

PROBLEMA 1: Senha salva sem criptografia
  Arquivo  : lib/providers/auth_provider.dart
  O que é  : A senha do usuário está salva em texto puro
             no armazenamento local do dispositivo.
  Risco    : Se alguém acessar o armazenamento interno do
             aparelho, consegue ver a senha.
  Solução  : Migrar para Firebase Authentication — o Firebase
             cuida da segurança das senhas automaticamente.

PROBLEMA 2: Qualquer pessoa pode acessar telas sem login
  Arquivo  : lib/app/routes.dart
  O que é  : Não há verificação se o usuário está logado
             antes de mostrar as telas do app.
  Risco    : Uma pessoa pode digitar o link direto e entrar
             sem passar pelo login.
  Solução  : Adicionar um redirecionamento automático para
             a tela de login se não estiver autenticado.

PROBLEMA 3: Remédios não separados por usuário
  Arquivo  : lib/providers/medication_provider.dart
  O que é  : Os remédios são salvos numa lista geral,
             sem identificar a qual usuário pertencem.
  Risco    : Se dois usuários usarem o mesmo dispositivo,
             um vê os remédios do outro.
  Solução  : Vincular cada remédio ao ID do usuário logado
             e separar os dados por usuário.

PROBLEMA 4: Chaves do Firebase no repositório público
  Arquivo  : lib/firebase_options.dart
  O que é  : As chaves de conexão com o Firebase estão
             visíveis no código no GitHub.
  Risco    : Baixo por enquanto (Firebase tem regras de
             segurança), mas não é uma boa prática.
  Solução  : Configurar regras de segurança no Firebase
             Console para limitar o acesso.

─────────────────────────────────────────────────────────────
🟠 IMPORTANTES — Devem ser resolvidos em breve
─────────────────────────────────────────────────────────────

PROBLEMA 5: Firebase instalado mas não usado
  Arquivo  : lib/main.dart e pubspec.yaml
  O que é  : O Firebase é inicializado mas toda a lógica
             de autenticação ainda usa SharedPreferences.
  Solução  : Próximo passo é migrar auth_provider.dart
             para usar Firebase Authentication de verdade.

PROBLEMA 6: userId 'current_user' fixo
  Arquivo  : lib/screens/user/medications_screen.dart
  O que é  : O ID do usuário ao salvar remédios está
             com o valor fixo 'current_user' no código.
  Solução  : Ler o ID real do authProvider.

PROBLEMA 7: HealthTipModel não é usado
  Arquivo  : lib/screens/user/health_tips_screen.dart
  O que é  : O modelo de dicas de saúde foi criado mas a
             tela usa um formato diferente (Map).
  Solução  : Refatorar a tela para usar o HealthTipModel.

PROBLEMA 8: Dependências instaladas sem uso
  Arquivo  : pubspec.yaml
  Pacotes  : riverpod_annotation, google_fonts,
             flutter_local_notifications, intl,
             firebase_auth, cloud_firestore
  O que é  : Estão declarados no projeto mas nenhum
             desses pacotes é usado no código atual.
  Impacto  : Aumenta o tamanho do app e o tempo de build.
  Solução  : Remover os não usados; usar firebase_auth e
             cloud_firestore quando migrar para Firebase.

─────────────────────────────────────────────────────────────
🟡 MENORES — Melhorias de qualidade
─────────────────────────────────────────────────────────────

PROBLEMA 9: Números fixos na Home
  Tela Home mostra sempre "12 farmácias" e "8 dicas"
  independentemente dos dados reais.

PROBLEMA 10: Busca e filtros de farmácias sem lógica
  A barra de busca e os filtros de farmácias são visuais
  mas não filtram a lista de verdade.

PROBLEMA 11: Botões sem ação no Perfil e Farmácias
  "Notificações", "Editar perfil", "Alterar senha",
  "Ligar" para farmácia — todos abrem mas não fazem nada.

PROBLEMA 12: CI/CD sem testes automáticos
  O deploy automático não roda testes antes de publicar.
  Código quebrado pode ir para o ar sem avisar.

PROBLEMA 13: Assets não declarados no pubspec.yaml
  As pastas assets/images/ e assets/icons/ existem mas não
  estão configuradas no pubspec.yaml, então imagens
  adicionadas lá não aparecem no app.
